## 2. システム概要


**本システムは、複数のユーザーがチャットルームに参加し、メッセージをリアルタイムに送受信できるWebアプリケーションとする。**

ユーザー認証、メッセージ履歴の保存、通信ログの記録に対応する。また、Docker環境で動作できる構成とする。

### 2.1 現在の環境

- Node.js = v24.21.0（LTS）

- npm = 11.19.0

## 4. 機能仕様
### 4.1 ユーザー認証機能
 - ユーザー名とパスワードで認証する。
 - 認証に成功したユーザーのみチャットを利用できる。
 - パスワードはハッシュ化して保存する。

### 4.2 メッセージ送受信機能
 - 入力したメッセージをサーバへ送信する。
 - サーバは同じルームのユーザーへメッセージを配信する。
 - 送信者名と送信日時を画面に表示する。
 - 空のメッセージは送信できないようにする。

### 4.3 チャットルーム機能
 - 複数のチャットルームを利用できる。
 - ユーザーはチャットルームへ参加・退出できる。
 - 異なるルームのメッセージは混在しないようにする。
### 4.4 メッセージ履歴機能
 - 送受信したメッセージをデータベースに保存する。
 - チャットルームごとに履歴を管理する。
 - 過去のメッセージを画面に表示できるようにする。

## 5. 通信仕様

### 5.1 通信方式

クライアントとサーバ間の通信にはWebSocketを使用する。

WebSocketにより、クライアントとサーバが双方向にデータを送受信できるようにする。

### 5.2 通信データ形式

**通信データはJSON形式とする。**

```json
例：

{
  "type": "message",
  "roomId": "room1",
  "content": "こんにちは"
}
```

**サーバは受信したデータを確認し、必要なユーザーへ配信する。**

### 5.3 通信エラー処理
 - サーバへの接続に失敗した場合、エラーを表示する。
 - 通信が切断された場合、接続状態を画面に表示する。
 - 不正なデータを受信した場合、処理を中止する。
 - 必要に応じて再接続できるようにする。

### 6.1 サーバ処理

**サーバはNode.jsで構築し、以下の処理を行う。**

---
## 7. データベース仕様

**データベースにはSQLiteを使用し、以下の情報を保存する。**
| テーブル | 保存内容 |
| --- | --- |
| users | ユーザーID、ユーザー名、パスワードハッシュ |
| rooms | ルームID、ルーム名 |
| messages | メッセージID、送信者ID、ルームID、本文、送信日時 |
---
## 8. ログ仕様

**サーバ上で以下の情報を記録する。**

 - クライアントの接続・切断
 - ユーザーのログイン結果
 - メッセージの送受信
 - チャットルームへの参加・退出
 - 通信エラーの発生

**パスワードなどの認証情報はログに記録しない。**

## 9. セキュリティ仕様
- ユーザー認証を実施する。
- パスワードをハッシュ化して保存する。
- 不正な入力を検証する。
- エラー画面に内部情報を表示しない。
- 本番環境ではHTTPSおよびWSSによる暗号化を使用する。
